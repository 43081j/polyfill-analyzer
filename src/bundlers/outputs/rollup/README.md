# Rollup Bundle Output Archive & Provenance Documentation

## 1. Overview
This directory contains downleveled JavaScript bundle artifacts generated by **Rollup 4** from the ECMAScript code samples (`es2011.js` through `es2026.js`). These artifacts serve as the reference baseline for deriving and validating AST-grep polyfill detection rules in `src/catalog/`.

## 2. Bundler Configuration & Plugin Setup
The Rollup adapter (`src/bundlers/rollup-adapter.ts`) is configured for static module encapsulation with externalized polyfills:
- **Plugins**: Uses `@rollup/plugin-node-resolve`, `@rollup/plugin-commonjs`, and a custom Babel transformation plugin (`customBabelPlugin`).
- **Transpilation Preset**: `@babel/preset-env` with `targets: { ie: '11' }`, `useBuiltIns: 'usage'`, `corejs: 3`, and `modules: false` (preserving ES import syntax for tree-shaking).
- **Post-Transform Rewrite**: The custom Babel plugin executes a regex replacement on transpiled module code:
  `code.replace(/import\s+(["'])(core-js\/[^"']+)\1\s*;/g, 'require($1$2$1);')`
  This converts bare `core-js` ES imports into CommonJS `require()` calls BEFORE Rollup processes the dependency graph.
- **Externalization**: Configures `external: (id) => id === 'core-js' || id.startsWith('core-js/') || id.startsWith('@babel/runtime')`. This excludes `core-js` from being bundled inline, leaving top-level `require(...)` statements cleanly exposed in the final IIFE bundle.

## 3. Artifact Generation Commands
To generate or rebuild all Rollup bundle artifacts in this directory, run from the project root:
```bash
# Generate Rollup bundles for all samples across all target environments
node dist/bundlers/generate.js --bundlers rollup

# Or execute TypeScript generator directly via tsx
npx tsx src/bundlers/generate.ts --bundlers rollup --targets es5 ie11 chrome50 modern
```

## 4. Provenance Tracing & AST-grep Rule Derivation
Because Rollup externalizes `core-js` modules and wraps output in an IIFE (`format: 'iife'`), polyfills appear as top-level CommonJS require calls directly inside the closure body.

### Example A: Promise (`es2015.js`)
- **Modern ES Source**: `export const fetchData = () => new Promise(res => res());`
- **Rollup ES5 Output**:
  ```javascript
  var SampleBundle = (function (exports) {
    'use strict';
    require("core-js/modules/es.promise.js");
    var fetchData = function fetchData() { return new Promise(function (res) { return res(); }); };
    exports.fetchData = fetchData;
    return exports;
  })({});
  ```
- **AST-grep Rule (`promise.yaml`)**: Directly matches `require("core-js/modules/es.promise.js")`.

### Example B: Object.assign (`es2015.js`)
- **Modern ES Source**: `export const merge = (a, b) => Object.assign(a, b);`
- **Rollup ES5 Output**:
  ```javascript
  require("core-js/modules/es.object.assign.js");
  var merge = function merge(a, b) { return Object.assign(a, b); };
  ```
- **AST-grep Rule (`object-assign.yaml`)**: Directly matches `require("core-js/modules/es.object.assign.js")`.

### Example C: Array.prototype.at (`es2022.js`)
- **Modern ES Source**: `const item = arr.at(-1);`
- **Rollup ES5 Output**:
  ```javascript
  require("core-js/modules/es.array.at.js");
  var item = arr.at(-1);
  ```
- **AST-grep Rule (`array-at.yaml`)**: Directly matches `require("core-js/modules/es.array.at.js")`.

## 5. False Positive Prevention & Verification
Modern reference outputs (`<sample>_modern.js`) are compiled with `format: 'esm'` and bypass `customBabelPlugin` entirely. Because no `core-js` require calls are injected, AST-grep scans return 0 detections, guaranteeing that catalog rules do not produce false positives on native modern JavaScript.
