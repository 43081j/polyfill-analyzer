# SWC Bundle Output Archive & Provenance Documentation

## 1. Overview
This directory contains downleveled JavaScript bundle artifacts generated by **SWC (`@swc/core` 1.4)** from the ECMAScript code samples (`es2011.js` through `es2026.js`). These artifacts serve as the reference baseline for deriving and validating AST-grep polyfill detection rules in `src/catalog/`.

## 2. Bundler Configuration & Plugin Setup
The SWC adapter (`src/bundlers/swc-adapter.ts`) utilizes SWC's high-speed Rust-based compiler for syntax downleveling and polyfill injection:
- **Parser Settings**: `jsc: { parser: { syntax: 'ecmascript' } }`.
- **Environment & Polyfill Config**: For older target environments (`es5`, `ie11`, `chrome50`), configures `env`:
  - `targets: 'ie 11'` or `'chrome 50'`.
  - `mode: 'usage'`: SWC scans AST nodes for ES feature usage and automatically injects required polyfills from `core-js`.
  - `coreJs: '3'`: Directs polyfill specifiers to `core-js@3` module paths.
- **Module Encapsulation**: Configured with `module: { type: 'es6' }`. When emitting standalone script files without an external bundler wrapper, SWC outputs clean CommonJS `require("core-js/modules/...";)` headers.

## 3. Artifact Generation Commands
To generate or rebuild all SWC bundle artifacts in this directory, run from the project root:
```bash
# Generate SWC bundles for all samples across all target environments
node dist/bundlers/generate.js --bundlers swc

# Or execute TypeScript generator directly via tsx
npx tsx src/bundlers/generate.ts --bundlers swc --targets es5 ie11 chrome50 modern
```

## 4. Provenance Tracing & AST-grep Rule Derivation
SWC's `mode: 'usage'` engine injects exact module dependency paths identical to Babel, ensuring that AST-grep rules operate seamlessly across both Babel-based and SWC-based build pipelines.

### Example A: Promise (`es2015.js`)
- **Modern ES Source**: `const delay = ms => new Promise(r => setTimeout(r, ms));`
- **SWC ES5 Output**:
  ```javascript
  "use strict";
  require("core-js/modules/es.promise.js");
  var delay = function(ms) { return new Promise(function(r) { return setTimeout(r, ms); }); };
  ```
- **AST-grep Rule (`promise.yaml`)**: Matches `require("core-js/modules/es.promise.js")`.

### Example B: Object.assign (`es2015.js`)
- **Modern ES Source**: `const updated = Object.assign({ active: true }, user);`
- **SWC ES5 Output**:
  ```javascript
  "use strict";
  require("core-js/modules/es.object.assign.js");
  var updated = Object.assign({ active: true }, user);
  ```
- **AST-grep Rule (`object-assign.yaml`)**: Matches `require("core-js/modules/es.object.assign.js")`.

### Example C: Array.prototype.at (`es2022.js`)
- **Modern ES Source**: `const tail = arr.at(-1);`
- **SWC ES5 Output**:
  ```javascript
  "use strict";
  require("core-js/modules/es.array.at.js");
  var tail = arr.at(-1);
  ```
- **AST-grep Rule (`array-at.yaml`)**: Matches `require("core-js/modules/es.array.at.js")`.

## 5. False Positive Prevention & Verification
Modern reference artifacts (`<sample>_modern.js`) compile with `jsc.target: 'es2022'` and omit the `env` usage configuration. This produces pure modern JS without any `core-js` require statements, ensuring that AST-grep scans return 0 detections and validating the absence of false positives.
